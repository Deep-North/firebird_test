# Общий древовидный план тестирования JOIN (только тесткейсы)

1. Типы JOIN и базовая корректность
   1. INNER JOIN
       1. Совпадение по одному ключу (1:1)
       2. Совпадение по одному ключу (1:N)
       3. Нет совпадений → пустой результат
       4. Совпадения при дубликатах ключа в обеих таблицах (N:M) → декартово по совпавшим ключам
   2. LEFT [OUTER] JOIN
       1. Есть совпадения + есть строки без совпадений (проверка NULL справа)
       2. Нет совпадений вообще → все строки слева, справа NULL
       3. Дубликаты справа (1:N) → размножение строк слева
   3. RIGHT [OUTER] JOIN
       1. Симметричные проверки к LEFT JOIN (проверка NULL слева)
   4. FULL [OUTER] JOIN
       1. Есть пересечение + есть непересекающиеся строки с обеих сторон
       2. Нет пересечения → все строки обеих таблиц, с NULL на противоположной стороне
       3. Дубликаты ключей → корректное размножение в зоне пересечения
   5. CROSS JOIN
       1. Размер результата = |A| * |B|
       2. Пустая таблица → пустой результат
---
2. Условия соединения (ON) и предикаты (WHERE)
    1. ON с равенством (=)
        1. Простое равенство по одному полю
        2. Составной ключ (несколько полей)
    2. ON с неравенствами (<, >, BETWEEN)
    3. ON с выражениями
        1. ON a.col = b.col + 1
        2. ON COALESCE(a.col, ...) = ...
    4. ON с NULL
        1. NULL в ключах: a.col = b.col не матчится при NULL
    5. Разница ON vs WHERE для OUTER JOIN
        1. Фильтр в WHERE превращает LEFT JOIN в INNER (на примере WHERE b.col = ...)
        2. Фильтр в ON сохраняет строки слева (на примере ON ... AND b.col = ...)
---
3. Несколько JOIN в одном запросе
    1. Цепочка A JOIN B JOIN C
        1. Корректность результата при разных кардинальностях
        2. Проверка порядка соединений (логическая эквивалентность)
    2. Смешанные типы (LEFT + INNER, LEFT + FULL)
       1. Проверка сохранения строк “внешней” стороны
       2. Проверка NULL-распространения
    3. Self-join
       1. Иерархия (parent_id)
       2. Исключение самосовпадения (a.id <> b.id)
---
4. JOIN и агрегаты/группировки
    1. JOIN + GROUP BY
        1. Агрегация после LEFT JOIN (строки без совпадений → COUNT(b.id)=0)
        2. Дубликаты справа → корректный COUNT/SUM
    2. JOIN + HAVING
        1. Фильтрация групп, включая группы с NULL-частью
---
5. JOIN и подзапросы
    1. JOIN с derived table (подзапрос в FROM)
        1. Подзапрос агрегирует, затем JOIN
        2. Подзапрос фильтрует, затем JOIN
    2. EXISTS/NOT EXISTS как альтернатива JOIN
        1. Эквивалентность результата (где применимо)
---
6. JOIN и сортировка/лимиты
    1. ORDER BY по полям разных таблиц
        1. Стабильность/корректность сортировки при NULL
    2. ROWS / FIRST/SKIP (если используется)
        1. Лимит после JOIN (корректность количества и порядка)
---
7. Типы данных и сравнения в JOIN
    1. Числа разных типов (INT/BIGINT/NUMERIC)
    2. Строки и коллации (case-sensitive/insensitive)
    3. Даты/время (DATE, TIME, TIMESTAMP)
    4. CHAR vs VARCHAR (паддинг пробелами)
---
8. Ошибки/негативные кейсы (валидность SQL)
    1. Неоднозначные имена колонок без алиасов → ошибка
    2. Ссылка на несуществующее поле/таблицу → ошибка
    3. Некорректный синтаксис JOIN → ошибка
    4. Несовместимые типы в условии (где Firebird не делает приведение) → ошибка/предупреждение
